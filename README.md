# go-items-api
 
Учебный REST API объявлений на Go. Написан, чтобы разобраться с языком
и с тем, как тестировать HTTP-сервисы на Go без поднятия сервера.
 
Только стандартная библиотека, без внешних зависимостей.
Нужен Go 1.22 или новее — маршрутизация использует шаблоны с методом и параметрами пути.
 
## Запуск
 
```bash
go run main.go
```
 
Сервер слушает порт `8080`. Данные хранятся в памяти и пропадают при перезапуске.
 
## Ручки
 
### `POST /items` — создать объявление
 
```bash
curl -i -X POST http://localhost:8080/items \
  -H "Content-Type: application/json" \
  -d '{"name":"Кресло","price":3500}'
```
 
| Ситуация | Код |
|---|---|
| Объявление создано | `201` |
| Тело не разбирается как JSON нужной формы | `400` |
| Пустое имя или имя из пробелов | `422` |
| Отрицательная цена | `422` |
| Метод не POST | `405` с заголовком `Allow: POST` |
 
Цена `0` допустима — «отдам даром».
Идентификатор назначает сервер; `id`, переданный клиентом, игнорируется.
В сообщении об ошибке `422` указывается поле, которое нужно исправить.
 
### `GET /items/{id}` — получить объявление
 
```bash
curl -i http://localhost:8080/items/1
```
 
| Ситуация | Код |
|---|---|
| Объявление найдено | `200` |
| Нет объявления с таким id | `404` |
| Метод не GET | `405` с заголовком `Allow: GET, HEAD` |
 
## Тесты
 
```bash
go test -v
```
 
Обработчики тестируются через `httptest.NewRecorder`, без сети.
Ручка чтения тестируется через тот же маршрутизатор (`newRouter`), что использует сервер:
так проверяется и обработчик, и шаблон пути, к которому он подключён.
 
Что покрыто:
 
**Создание**
 
- успешное создание: код, тело ответа, запись в хранилище;
- неверный метод — `405` и заголовок `Allow`;
- неразбираемое тело (табличный тест);
- невалидные данные: код и упоминание поля в сообщении об ошибке (табличный тест);
- граница цены: `-1` отклоняется, `0` принимается; для нулевой цены проверяется
  сырое тело ответа, чтобы поле `price` не пропало.
**Чтение**
 
- успешное чтение: в хранилище два объявления, запрашивается второе —
  проверяется, что отдаётся объявление именно по запрошенному id;
- несуществующий id — `404` и сообщение об ошибке;
- неверный метод — `405` и заголовок `Allow`.
Каждый тест начинает с чистого хранилища и не зависит от порядка запуска.
